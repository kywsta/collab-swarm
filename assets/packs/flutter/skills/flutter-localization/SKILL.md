# Localization

Every user-visible string is a key. Not because the app is translated today, but because a literal in a widget tree is a string nobody can find, review, or change in one place.

Strings live in `{{i18n.source}}` and are read as `{{i18n.call}}`. Generated by `{{i18n.sdk}}`; run the project's `generate` check after editing a source file.

## 1. Add the key

Name it after the screen and the role, not the text: `items.emptyTitle`, not `items.nothingHereYet`. A key named after its current wording is renamed every time copy changes, and every rename is a chance to miss a locale.

Add the key to **every** supported locale in the same commit. A key present in one locale and missing in another either fails the build or falls back silently, and the silent case ships.

Group keys by feature, mirroring `features/`. A shared string — a cancel button, a generic error — goes in a common group, and there is exactly one of each.

Done when the key exists in every locale, is named after its role, and sits in its feature's group.

## 2. Parameters and plurals

A message with a value takes a **parameter**; it is never assembled from concatenated fragments. Word order differs between languages, and a concatenation hard-codes one of them.

A count uses the generator's plural form, with every category the locale needs. `'$count items'` is wrong in English at one, and wrong in more places elsewhere.

Dates, times, numbers and currency are formatted through `intl` against the active locale — never `toString()`, never a hand-written pattern.

Done when no user-visible sentence is built by concatenation and every count goes through a plural form.

## 3. Switch locale

The selected locale is a lifecycle value with one owner: a module holding the snapshot and a replaying stream, persisted to preferences, read by the app's `MaterialApp` and by anything that formats. See `flutter-state-management`.

A locale change rebuilds from the top. Nothing caches a formatted string across it, and nothing stores a translated string in state — state holds the value, the widget formats it.

Done when changing locale re-renders every visible string, and no translated text is held in state.

## 4. Review the strings a feature added

Before the ticket closes, read the keys the diff added in each locale. Look for the three that always appear: a key added to one locale only, an English string pasted as the placeholder for another locale, and a sentence assembled from two keys.

## Checklist

- [ ] No user-visible literal in any widget
- [ ] Every new key present in every supported locale
- [ ] Keys named after screen and role, grouped by feature
- [ ] Parameters, not concatenation; plural forms for counts
- [ ] Dates, numbers and currency formatted against the active locale
- [ ] Translated text is never stored in state
- [ ] `generate` run after editing a translation source
