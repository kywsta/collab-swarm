# Changelog

## Unreleased

- **The documented command is `npx collab-swarm`.** The package installs three bins — `collab-swarm`, `swarm` and `cswarm` — and every generated document, hint and usage line now names the first. `npx swarm` resolves an *unrelated* package on the npm registry for anyone without a local install, so it was never safe to put in a file an agent reads in a fresh container. Somebody who has installed it can still type `swarm`; nothing tells them to. Usage lines follow whichever bin was invoked, and `steps` still reads `npx swarm` out of a pack written against the old name.
- **Default packs, starting with Flutter.** `npx collab-swarm add flutter` attaches a written-and-tested pack that ships inside collab-swarm — no install step, version-locked to the CLI. It covers a Flutter app end to end: a concern router, ten concern skills (API and data stack, Riverpod state, dependency injection, failures, UI, navigation, storage, observability, push, localization), a screen review, an architecture reference, path-scoped rules for each, and the `generate` check they need. `npx collab-swarm pack list` shows what ships; `init` offers the one whose marker files are in the repository.
- **A pack can ask questions.** A stack has a fixed core and a handful of slots every team fills differently. A pack declares those as `options`; `add` and `init` ask them once, and the answers are recorded in `collab-swarm.yml` so a teammate's `sync` reproduces the same files without another interview. Three mechanisms use an answer: `if` decides whether a skill, rule, check or package exists at all; `<!-- swarm:if -->` blocks and inline spans decide the prose; `{{option.var}}` decides the identifiers. `npx collab-swarm pack options <pack>` re-answers them and re-applies everything they decide — a skill an answer rules out is removed from every target, not left behind. The Flutter pack asks seven: push, analytics, crash reporting, logging, local database, localization, and environment configuration.
- **A pack can declare its stack.** `stack` in the manifest carries the architecture summary, the project layout, the conventions that hold everywhere, and the libraries the stack is built on — joined with the packages the chosen options bring in. It is rendered into `AGENTS.md` and `CLAUDE.md`, so an agent reads it before it decides which skill to open, and reaches for a library the project already has instead of adding one. Nothing is written to the project's dependency manifest.
- **`init` asks how this project gets its stack skills.** A default pack, a pack written from this repository's own code, or not yet. Choosing the second scaffolds `.collab-swarm/packs/<name>/` and writes a `BRIEF.md` from what the project said, which `to-pack` now reads before it researches. `--pack <name|custom|none>` and `--options k=v,k=v` make the whole interview scriptable.
- **`validate` reports an unresolved pack variable or an unclosed conditional.** Both publish into the agent files verbatim, so both are errors rather than something to notice later. `doctor` reports an answer a pack no longer offers, and an option nothing answered.
- **Skills for your own stack.** `to-pack` researches the repository — its dependency manifest, its build and lint config, and features already built end to end — and writes the skills and rules that implement in it: a concern router, one skill per concern, path-scoped rules, and the checks they need. The pack lands in `.collab-swarm/packs/<name>/`, is attached with `npx collab-swarm add`, and is vendored into every agent target by `sync` like any other. `npx collab-swarm pack new <name>` scaffolds the layout and manifest first, so roles are right before any prose is written.
- **Two new skill roles.** `router` selects the smallest applicable concern set for each red-green slice, so a ticket touching one concern loads one skill rather than the whole pack; `implement` uses it when a pack ships one. `review` reviews a surface a diff cannot judge, and `deliver-change` runs every one at feature review. Neither may be named in a ticket's `skills` — only `ticket` may, as before.
- **`validate` reports a skill with no description and a rule with no `paths`.** The first is never opened by an agent; the second is loaded into every turn. Both were previously silent.
- **`npx collab-swarm steps`.** The installed skills, read back as an execution map: the sequence each one runs, what finishes each step, which skill it hands work to, which `swarm` commands and plan files it touches, and which rules are in force while it runs. `steps <skill>` opens one in full; `steps --rules` inverts the view to show every step a rule governs and the file that brought it into force. Derived from the payload in the checkout — nothing is recorded, and the workflow still keeps no event log.
- The CLI command is now `swarm` (was `collab-swarm`). The npm package, config files, and GitHub repository remain `collab-swarm`. The `cswarm` alias is unchanged.

## 0.1.0

First release. Extracted from the agentic delivery workflow built and used to deliver apps in production, and generalised away from Flutter.

- **Workflow.** `requirements → specification → tickets → implementation → review → complete`, one plan per feature, committed to the repository.
- **Delivery board.** A Markdown feature register joined with Git claims: a pushed branch claims a row, a completed plan on the default branch marks it done, and dependencies, human gates and product decisions derive the blocked state.
- **Validator.** Plan shape, required sections, unfilled template text, ticket front matter, dependency cycles, status coherence, and ticket skills checked against the installed packs.
- **Check runner.** One configured command set that a human, an agent and CI all run, with focused and CI variants.
- **Targets.** Claude Code, the AGENTS.md standard, OpenAI Codex, Cursor, OpenCode and Google Antigravity, chosen at `init`. Targets sharing a directory share one copy of the payload.
- **Packs.** Language and framework skills, rules and checks added after the fact, with roles that decide how each skill may be reached.
- **Sync.** Vendored payload with a manifest, so an upgrade rewrites what it owns, reports what you edited, and removes what an older version left behind.
